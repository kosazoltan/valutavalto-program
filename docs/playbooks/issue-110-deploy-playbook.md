## 3. Bulk init: cash_balance osszes branch-re

```bash

TOKEN="$(curl -s -X POST https://excvaluta.com/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"..."}' | jq -r .token)"

# Issue #110 retrofit
curl -X POST "https://excvaluta.com/api/v1/cash-balances/init-all-branches" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Idempotency-Key: issue110-retrofit-$(date +%Y%m%d)"
```

## 4. Penztar-client sync retry

Az EBC Kft. penztar-client (offline outbox-ban 7 pending tranzakcio):

```
# Windows: C:\Program Files\Penztar\Valuta Penztar.exe
# (vagy dev: frontend-react-ben "Sync Now" gomb)
```

A kliens automatikusan retry-oljon — a SyncEngine 3-URL fallback + exponential
backoff-ot hasznal. Ha az offline queue-ban "VEBCxxx" bizonylat latszik, az
ott varakozik.

Tippek:
- `VEBC000004` bizonylat: tegnapi test-tranzakcio, kulonos figyelmet igenyel.
- Ha a sync 409 Conflict-et ad vissza (duplikatum), az NORMALIS — a V155
  migration pre-check-je mar elbirta a napot.

## 6. Monitoring + alerting

A `SessionOpenService` lazy-init fallback-je WARN log-ot ir:
```

```

Ha ilyet latsz production log-ban Hetzner-en, az azt jelenti, hogy egy branch
a bulk init elott sessiont nyit. Ez **megoldja magat** (a lazy-init ott is mukodik),
de jelzes ertekelo: az admin bulk init hianyzott/kesett.
