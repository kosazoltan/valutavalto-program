# Operating Model

This repository uses phase-separated agentic development.

Phases:
1. Contract
2. Tests
3. Freeze
4. Repo map
5. Patch
6. Validate
7. Debug
8. Audit
9. Counter-review
10. Report

Reason:
- reduces context confusion
- prevents test hacking
- keeps diffs small
- creates evidence
- separates coding from reviewing
