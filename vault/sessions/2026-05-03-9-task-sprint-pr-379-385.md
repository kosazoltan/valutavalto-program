## Kulcs technikai döntések

### Task 7 (P1.3) — Audit kontextus
A `loadPersistedToken` átírása in-memory + refresh-cookie bootstrap-ra TÖBB követelménnyel jár:
- `App.tsx` restore flow változatlanul OK (már `await loadPersistedToken()`-t hív)
- Response interceptor `logger.error` → `logger.debug` ha refresh-cookie failure (smoke teszt
  console.error count `<= 2`, különben fail)

- `hasPersistedToken` web-en mindig `true` (App.tsx mindig hívja a `loadPersistedToken`-t)

### Task 9 (Jackson 3) — BLOCKED, defer

**Tényadatok:**
- Jackson 3.0.4 stable (2026-01-21, `tools.jackson.*` namespace)
- Spring Boot 4.0.6 default Jackson 3, mi `spring-boot-jackson2` stop-gap-pel + `JacksonConfig.java`-val maradunk Jackson 2-n
- `jjwt-jackson:0.13.0` még csak Jackson 2-t támogat — NINCS `tools.jackson` verzió
- Saját kódunkban 41 fájl, 70 import (18 annotation Jackson 3 alatt is változatlan, 52 import = migráció igényű)

**Konklúzió:** A teljes Jackson 3 migráció jelenleg blokkolva van a jjwt-jackson által.
Két opció a sprint-re (külön session-ben): (1) várjuk a jjwt új release-jét, vagy (2) jjwt
lecserélése `nimbus-jose-jwt` / `auth0/java-jwt`-re. Részletek: GitHub issue #386.

A jelenlegi stop-gap STABIL — production deploy SUCCESS minden mergelt PR után, 1115/1115
backend test PASS. Nem hiba, hanem long-term technical debt.

## Lessons learned

1. **Branch fork-olás közben oda kell figyelni.** A P1.8 branch véletlenül a P1.3 branch-ről
   lett létrehozva, és a P1.3 commitot is tartalmazta. `git rebase --onto main 177255c2 fix/...`
   javítása.
2. **In-memory token storage + Playwright** — minden page.goto egy ÚJ page load, ami a sessiont
   eldobja. Minden teszt vagy login flow-t tartalmaz, vagy a refresh-cookie mock-ot.
3. **Console error count smoke teszt** — minden console.error növeli a count-ot, ezért a
   "normal failure" log szintjének DEBUG-nek kell lennie, ne ERROR.
4. **research-first protokoll** — Jackson 3 migrációhoz a research feltárta a jjwt-jackson
   blokkoló függőséget → tisztességes "defer + dokumentál" döntés a 9. task-on, nem
   félkész 41-fájlos refaktor risk-tel.
