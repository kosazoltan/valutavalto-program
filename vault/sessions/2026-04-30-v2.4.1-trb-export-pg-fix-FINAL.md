# v2.4.1 release session — F8 TRB Export PostgreSQL type inference fix

## TL;DR

A v2.3.X / v2.4.0-ban felfedezett **F8 TRB Export funkcionális bug** tényalapú root cause-szal javítva. Hetzner production-on ellenőrzött: HTTP 500 → HTTP 401 (auth, NEM 500 többé), backend log 0 PSQL hiba.

## A reprodukcióból a fix-ig — tényalapú lépések

### 1. TÉNY: Hibareprodukció

```
GET https://excvaluta.com/api/v1/trb-export/preview?date=2026-04-29
HTTP 500 (előtte)
Frontend: "Nem sikerült betölteni az adatokat. Próbáld újra."
```

### 2. TÉNY: Hetzner SSH backend log

```
Apr 30 05:02:16 java[204480]: org.postgresql.util.PSQLException: ERROR: could not determine data type of parameter $3
SQL: ... and (? is null or im1_0.movement_date>=?) and (? is null or im1_0.movement_date<=?) ...
Stack: TrbExportService.buildBankFlowLines(TrbExportService.java:365)
```

Két reprodukált hiba: `05:02:16` + `05:02:37`.

### 3. TÉNY: Root cause

**JPQL pattern:**
```java
@Query("... AND (:startDate IS NULL OR m.movementDate >= :startDate) " +
       "AND (:endDate IS NULL OR m.movementDate <= :endDate) ...")
```

A Hibernate ezt két külön `?` SQL paraméterre fordítja. A PostgreSQL JDBC driver az `IS NULL` operandus pozíciójához tartozó paraméter típusát NEM tudja kikövetkeztetni → `PSQLException: could not determine data type of parameter $3`.

### 4. TÉNY: Precedens (NEM találgatás)

`AuditLogRepository.java` MÁR használja a megoldási mintát:
```java
"(CAST(:from AS timestamp) IS NULL OR a.created_at >= :from) AND ..."
```

Ez production-ban WORKS — explicit type-hint a JDBC driver-nek.

### 5. FIX

**Iter1 (`810728f6`)**: `CAST(:startDate AS LocalDate) IS NULL OR ...`
- Backend test 1038/1038 PASS
- Verzió bump 2.4.0 → 2.4.1

**Iter2 (`01c640c8`)** — Sourcery 2 P2 finding fix:
- `CAST(... AS LocalDate)` → `CAST(... AS DATE)` (SQL-szabványos, portabilis)
- Magyar komment 5 sor → 3 sor
- Backend test 1038/1038 PASS
