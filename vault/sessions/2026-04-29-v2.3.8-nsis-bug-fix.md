## Fix #1: PowerShell `-like` parser error → `-EncodedCommand` UTF-16LE base64

**Tünet (v2.3.7 Setup #1+#2):**
```
You must provide a value expression following the '-like' operator.
    + CategoryInfo          : ParserError: (:) [], ParentContainsErrorRecordException
    + FullyQualifiedErrorId : ExpectedValueExpression
```

**Forrás:** A `Penztar-Setup.nsi` és `Penztar-Cleanup.nsi` 8 helyen használt inline PowerShell-t a "scoped postgres/java kill"-hez. A NSIS+PowerShell quote-ágyazás (`'powershell ... { $$_.Path -like ''*BestChange*'' } ...'`) az NSIS-szintű `''` → `'` és `$$` → `$` escape-ek után PowerShell-szinten néha szétesett (cmd-elemzés, idézőjel-egyensúly).

**Fix:** Minden inline PowerShell-t **`-EncodedCommand` UTF-16LE base64**-re cseréltünk, ami quote-mentes és parser-immune.

**Generátor:** `installer/scripts/compute-b64.ps1` — auditálható, megismételhető, négy bázis-string base64-ét generálja.

**4 base64 konstans (`!define` a NSIS-fájl tetején):**
| Konstans | PowerShell forrás |
|---|---|
| `PS_KILL_PG_B64` | `Get-Process postgres -ErrorAction SilentlyContinue \| Where-Object { $_.Path -like '*BestChange*' } \| Stop-Process -Force -ErrorAction SilentlyContinue` |
| `PS_KILL_JAVA_B64` | `Get-Process java     -ErrorAction SilentlyContinue \| Where-Object { $_.Path -like '*BestChange*' } \| Stop-Process -Force -ErrorAction SilentlyContinue` |
| `PS_CHECK_PG_B64` | `if (Get-Process postgres -EA 0 \| Where-Object { $_.Path -like '*BestChange*' }) { exit 1 } else { exit 0 }` |
| `PS_CHECK_JAVA_B64` | `if (Get-Process java     -EA 0 \| Where-Object { $_.Path -like '*BestChange*' }) { exit 1 } else { exit 0 }` |

**Verifikáció:** mind a 4 base64 dekódolódott + lefutott `EXIT=0` (no parser error).

## Fix #3: Backend wait timeout 60 iter → 90 iter (120s → 180s)

**Tünet (v2.3.7 Setup #3 SUCCESS):**
A "Varakozas a Backend szerverre (ez 30-60 masodpercig tarthat)..." üzenet alatt a wizard úgy tűnt, mintha elakadt volna, **DE** a backend valójában 14.5 sec alatt feláll. A user által észlelt "elakadás" a NSIS UI nem-progressive blocking miatt + hibás "30-60 mp" szöveg-jelzés volt.

**Fix (`Penztar-Setup.nsi` L897-919):**
```diff
-DetailPrint "  Varakozas a Backend szerverre (ez 30-60 masodpercig tarthat)..."
+DetailPrint "  Varakozas a Backend szerverre (ez 30-90 masodpercig tarthat, lassu rendszeren akar 180 mp-ig)..."
 StrCpy $R0 0
 be_svc_wait:
     IntOp $R0 $R0 + 1
-    ${If} $R0 > 60
+    ${If} $R0 > 90
         IfSilent be_svc_done
-        MessageBox MB_OK|MB_ICONEXCLAMATION "FIGYELMEZTETES: A Backend szerver nem indult el 120 masodpercen belul.$\r$\n..."
+        MessageBox MB_OK|MB_ICONEXCLAMATION "FIGYELMEZTETES: A Backend szerver nem indult el 180 masodpercen belul.$\r$\n..."
```

A loop `Sleep 2000` (2 sec/iter) marad változatlan → 90 iter × 2 sec = 180 s timeout.

**Indok:** ESET realtime + lassú HDD + Spring Boot 4.0.6 + 165 Flyway migration esetén a 14.5 sec ideál-eset, de pesszimista rendszer-konfiguráción 60-90 sec is realisztikus. A 180 s biztonsági tartalék.
