# v2.3.31 Flyway Emergency Incident

## Tünet

A Hetzner production HTTP **502** Bad Gateway 4 deploy-on keresztül:
- v2.3.27 (PR #292) — első fail
- v2.3.28 (PR #293)
- v2.3.29 (PR #294)
- v2.3.30 (PR #295)

Minden deploy a Spring Boot startupban Flyway migrate során fail-elt.

## Root cause

A v2.3.27 (V168) és v2.3.29 (V169) Flyway migration-ok az `INSERT INTO denomination (..., active, ...)` syntax-ot használták, DE a Hetzner production DB schema-ban a `denomination` tábla **CSAK `is_active` columnával** rendelkezik (V3_7 dynamic-add migration-ban). Lokálisan (fresh install Hibernate ddl-auto=update) az oszlop neve `active` lehet — production-on a tényleges schema más.

```sql
-- V168 (BUG):
INSERT INTO denomination (..., active, ...) VALUES (..., true, ...);

-- Production schema:
denomination(.., is_active, ..)  -- V3_7 dynamic-add column
-- "active" column NEM létezik
```

Hibaüzenet:
```
ERROR: column "active" of relation "denomination" does not exist
```

## Fix

**v2.3.31 emergency hotfix (PR #296, admin-merged):**

1. **V168 fájl javítva** — `active` → `is_active`
2. **V169 fájl javítva** — `active` → `is_active`
3. **V170 NEW** — emergency repair migration (idempotent backfill `is_active`-tel)
4. **`spring.flyway.repair-on-migrate=true`** beállítva, hogy a checksum-mismatch automatikusan repair-elje a V168/V169-et

## Tanulság

> **"Flyway migration script-eken FUTTASS lokális tesztet a production schema-másolatán is, NEM csak a fresh installon."**

A lokális dev DB Hibernate auto-create módban épült (ddl-auto=update), és más oszlop-neveket generált, mint a production-szabályos Flyway-managed schema. A production-prep workflow:

1. **Schema dump** a production DB-ből: `pg_dump --schema-only`
2. **Lokális test DB** a dump alapján (NEM Hibernate auto-create)
3. **Flyway migrate** futtatása a test DB-n az új migration-okkal
4. **Smoke test** a production-szabályos schema-n
5. CSAK ezután push + production deploy

## Iparági pattern

**Spring Boot Flyway + ddl-auto=none production-ben** — ez már a helyes irány. De a lokális dev környezetben is `ddl-auto=none` + Flyway-managed schema kellene, hogy a divergencia kizárt legyen.

**Fail-loud, repair-when-needed:**
- `spring.flyway.repair-on-migrate=true` PRODUCTION ONLY (Sourcery #296 P2 fix v2.3.32-ben — eredetileg globális, de a dev-ben loud-ot kell hagyni)
- Out-of-order: production OFF, dev ON (V169 deploy után V170 emergency cmd. flexibilitás)
